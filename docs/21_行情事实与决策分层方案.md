# 行情事实与决策分层方案

## 目标

把可重复计算的行情事实与需要结合用户意图、风险偏好和上下文的交易判断分开。行情工具不替 LLM 决定方向或是否交易，LLM 也不改写工具事实。

## 第一阶段：行情工具事实化

状态：已完成。

`analyze_market` 输出 `market_facts.v1`，核心字段包括：

- 价格与时间：`current_price`、`timestamp`、`recent_candles`
- 均线事实：`ma_regime`、`ma_alignment`、`ma_periods`、`ma_values`、`price_vs_ma`、`ma_slopes_pct`
- 结构事实：`swing_structure`、`swing_points`、`range_position`
- 关键位事实：`support_levels`、`resistance_levels`、`distance_to_levels_pct`、`level_details`
- 量价与辅助计算：`volume_state`、`volume_ratio`、`fib_v1`、`level_zones_v1`

行情计算结果先由单一、扁平的 `MarketFacts` 校验顶层字段类型；复杂字段继续使用 `dict` 和 `list`，
不为每个字段建立子类。内部计算和数据库仍使用稳定代码，工具在交给 LLM 前通过一个统一出口将
均线状态、摆动结构、量能、K线事件和关键位等分类值转换为中文。

`ma_regime` 仅表示机械均线算法结果，不是最终交易方向。它在内部使用 `bullish`、`bearish` 或
`mixed`，面向 LLM 时分别输出“均线偏多”“均线偏空”或“均线方向分化”。

工具、分析快照、数据库物理列和上下文摘要统一使用 `ma_regime`，不再输出、存储或传播 `trend`、`stance`、`bias`、`can_trade_now`、`why`、`wait_condition`、`triggered`、`side=wait`、`actionability`、`trigger_conditions`、`invalidation_conditions` 和 `risk_flags`。

## 后续上下文方案

原计划通过 `active_thesis_v1` 和 `decision_event_v1` 增加结构化记忆字段，该方向已经取消。目标方案改为保存不可变原始会话事件，通过 token 驱动的 compaction 和原文检索恢复上下文，详见 [22_Pi式上下文管理架构.md](22_Pi式上下文管理架构.md)。

交易动作仍由 LLM 基于行情事实、用户要求和风险约束生成，但历史观点和历史决策必须从原始事件中取证，不单独维护模型推断出的“当前观点”状态。

## 边界原则

- 工具负责观测和计算，不负责交易立场。
- LLM 负责解释、权衡和行动建议，并明确引用哪些事实。
- 用户观点与 LLM 决策分别记录，不能用最终涨跌反向改写历史判断。
- 后续 schema 通过版本号演进，不恢复含糊的 `trend` 字段。
