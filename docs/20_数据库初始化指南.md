# PostgreSQL 初始化指南

本文用于在一台新电脑上克隆项目后，快速启用分析快照和新版模拟单三表：
`journal_ideas`、`paper_orders`、`journal_events`。

## 适用范围

- 使用全新的 PostgreSQL 数据库。
- 使用当前仓库的 SQLAlchemy 模型建表。
- 本地开发推荐使用项目内独立 PostgreSQL 实例，把数据放在仓库 `var/postgres/` 下，避免影响同机其他业务库。

## 1. 推荐：项目内独立 PostgreSQL 实例

本项目的 PostgreSQL 只承载分析快照、模拟单和交易事件。若同一台机器上还有其他进程使用系统 PostgreSQL，不要把系统实例的 `data_directory` 从 `/var/lib/postgresql/...` 改到项目目录；那会影响同一个 PostgreSQL 实例里的所有数据库。

推荐单独启动一个项目实例：

| 项 | 值 |
| --- | --- |
| 数据目录 | `var/postgres/data` |
| 运行 socket | `var/postgres/run` |
| 日志 | `var/postgres/log/postgres.log` |
| TCP 监听 | `127.0.0.1:55432` |
| 数据库 / 用户 | `marketass` / `marketass` |

### 1.1 初始化项目数据目录

下面命令以 Ubuntu PostgreSQL 12 为例。若 `initdb` / `pg_ctl` 在 PATH 中，也可以直接替换为对应命令。

```bash
ROOT="$PWD"
PGROOT="$ROOT/var/postgres"
PGDATA="$PGROOT/data"
PGRUN="$PGROOT/run"

install -d -m 0755 "$ROOT/var"
install -d -m 0755 "$PGROOT"
install -d -m 0700 -o postgres -g postgres "$PGDATA"
install -d -m 0755 -o postgres -g postgres "$PGRUN"
install -d -m 0755 -o postgres -g postgres "$PGROOT/log"

runuser -u postgres -- /usr/lib/postgresql/12/bin/initdb \
  -D "$PGDATA" \
  --encoding=UTF8 \
  --locale=C \
  --auth-local=trust \
  --auth-host=scram-sha-256
```

如果仓库位于 `/root/...`，`postgres` 系统用户可能无法穿过上层目录。只在必要目录上授予“穿越目录”权限，不要开放系统 PostgreSQL 数据目录：

```bash
setfacl -m u:postgres:x /root

# 如果当前文件系统不支持 ACL，可对项目上层私有目录使用 group 执行权限：
chgrp postgres /root/pfs_liuyangtong
chmod g+x /root/pfs_liuyangtong
```

### 1.2 启动项目 PostgreSQL

```bash
ROOT="$PWD"
PGROOT="$ROOT/var/postgres"
PGDATA="$PGROOT/data"
PGRUN="$PGROOT/run"
PGLOG="$PGROOT/log/postgres.log"

runuser -u postgres -- /usr/lib/postgresql/12/bin/pg_ctl \
  -D "$PGDATA" \
  -l "$PGLOG" \
  -o "-p 55432 -h 127.0.0.1 -k $PGRUN" \
  start
```

创建项目数据库和应用账户：

```bash
runuser -u postgres -- psql -h "$PWD/var/postgres/run" -p 55432 -d postgres -v ON_ERROR_STOP=1 <<'SQL'
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_catalog.pg_roles WHERE rolname = 'marketass') THEN
    CREATE ROLE marketass LOGIN PASSWORD '111';
  ELSE
    ALTER ROLE marketass WITH LOGIN PASSWORD '111';
  END IF;
END
$$;
SELECT 'CREATE DATABASE marketass OWNER marketass'
WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = 'marketass')\gexec
ALTER DATABASE marketass OWNER TO marketass;
SQL
```

配置 `runtime/config/analysis_defaults.yaml`：

```yaml
database:
  postgres:
    dsn: "postgresql+psycopg://marketass:111@127.0.0.1:55432/marketass"
```

初始化业务表：

```bash
PYTHONPATH="$PWD/runtime:$PWD/src:$PWD" python3.12 -c \
  "from infrastructure.persistence.db import init_db; init_db(); print('database initialized')"
```

验证当前应用连接的确是项目实例：

```bash
pg_isready -h 127.0.0.1 -p 55432

PYTHONPATH="$PWD/runtime:$PWD/src:$PWD" python3.12 - <<'PY'
from sqlalchemy import inspect, text
from infrastructure.persistence.db import get_engine

required = {
    "analysis_snapshots",
    "journal_ideas",
    "paper_orders",
    "journal_events",
}
engine = get_engine()
with engine.connect() as conn:
    port = conn.execute(text("select inet_server_port()")).scalar()
tables = set(inspect(engine).get_table_names())
missing = sorted(required - tables)
if port != 55432:
    raise SystemExit(f"unexpected postgres port: {port}")
if missing:
    raise SystemExit(f"missing tables: {missing}")
print("project postgres ready")
PY
```

停止项目 PostgreSQL：

```bash
runuser -u postgres -- /usr/lib/postgresql/12/bin/pg_ctl \
  -D "$PWD/var/postgres/data" \
  stop
```

### 1.3 从旧系统库迁移数据（可选）

如果旧系统 PostgreSQL `5432` 上已有本项目数据，先停止应用或飞书 bot，再导出四张业务表到项目实例：

```bash
PGPASSWORD=111 pg_dump -h 127.0.0.1 -p 5432 -U marketass -d marketass --data-only --inserts \
  -t public.analysis_snapshots \
  -t public.journal_ideas \
  -t public.paper_orders \
  -t public.journal_events \
| PGPASSWORD=111 psql -h 127.0.0.1 -p 55432 -U marketass -d marketass -v ON_ERROR_STOP=1
```

该迁移只复制本项目业务表数据，不修改系统 PostgreSQL 的数据目录，也不影响同机其他数据库。

## 2. 备选：使用系统 PostgreSQL 或 Compose

本地已安装 PostgreSQL 时，创建数据库和应用账户：

```sql
CREATE USER marketass WITH PASSWORD 'change-me';
CREATE DATABASE marketass OWNER marketass;
```

也可直接使用项目的 Compose 配置仅启动数据库：

```bash
docker compose -f ops/docker-compose.yml up -d db
```

该 Compose 默认数据库与用户均为 `marketass`。生产环境请修改密码，并不要把包含真实凭证的配置提交到 Git。

## 3. 配置本地 DSN

复制模板：

```bash
cp runtime/config/analysis_defaults.example.yaml runtime/config/analysis_defaults.yaml
```

在 `runtime/config/analysis_defaults.yaml` 填写数据库连接。驱动名必须使用 `postgresql+psycopg`：

```yaml
database:
  postgres:
    dsn: "postgresql+psycopg://marketass:change-me@127.0.0.1:5432/marketass"
```

安装项目依赖后，`psycopg` 会由 `requirements.txt` 一并安装：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 4. 初始化或升级当前模型

从仓库根目录执行：

```bash
PYTHONPATH="$PWD/runtime:$PWD/src:$PWD" python -c \
  "from infrastructure.persistence.db import init_db; init_db(); print('database initialized')"
```

`init_db()` 会按当前 SQLAlchemy 模型创建不存在的表和索引；可重复执行。Web 服务和飞书服务启动时也会尝试调用它，但首次部署建议显式运行一次，以便立刻发现 DSN、网络或权限问题。

不要对新环境执行 `alembic upgrade/downgrade/stamp`。仓库中的历史 Alembic 链不作为当前新库初始化入口。

已有数据库若仍包含 `analysis_snapshots.trend` 或 `analysis_snapshots.stance`，先停止应用，再执行一次：

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 \
  -f ops/migrations/20260920_analysis_snapshots_ma_regime.sql
```

该迁移会把物理列统一为 `ma_regime`、规范化历史值、重建 `analysis_snapshot.v2` payload，并删除 `stance`。迁移脚本只执行一次。

## 5. 验证

执行下列命令确认关键表均可见：

```bash
PYTHONPATH="$PWD/runtime:$PWD/src:$PWD" python - <<'PY'
from sqlalchemy import inspect
from infrastructure.persistence.db import get_engine

required = {
    "analysis_snapshots",
    "journal_ideas",
    "paper_orders",
    "journal_events",
}
tables = set(inspect(get_engine()).get_table_names())
missing = sorted(required - tables)
if missing:
    raise SystemExit(f"missing tables: {missing}")
paper_order_columns = {column["name"] for column in inspect(get_engine()).get_columns("paper_orders")}
if "position_size" not in paper_order_columns:
    raise SystemExit("paper_orders missing column: position_size")
snapshot_columns = {column["name"] for column in inspect(get_engine()).get_columns("analysis_snapshots")}
if "ma_regime" not in snapshot_columns or {"trend", "stance"} & snapshot_columns:
    raise SystemExit("analysis_snapshots schema is outdated")
print("database ready")
PY
```

然后启动服务：

```bash
bash scripts/web_dev.sh
```

访问 `http://localhost:8000/chat`。当用户确认创建模拟单时，系统会在一个事务中写入一条 `journal_ideas`、一条 `paper_orders` 和一条 `journal_events`。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `未配置 database.postgres.dsn` | 检查本地 `analysis_defaults.yaml` 是否存在，且 `database.postgres.dsn` 非空。 |
| 连接被拒绝 | 确认 PostgreSQL 已启动、端口和主机正确；Docker 场景检查 `docker compose ... ps`。 |
| 权限不足 | 应用账户至少需要目标数据库的建表、建索引和读写权限。 |
| 聊天仍可用但模拟单报错 | 数据库初始化在服务启动中是 best-effort；查看启动日志中的 `[DB] 初始化跳过` 原因。 |
