# 轻量历史记录与模型取数施工方案

日期：2026-11-04

状态：已实施并完成本机验证。方案基于 [26_事件标识与模型取数边界分析报告.md](26_事件标识与模型取数边界分析报告.md)；实际差异与验收结果记录在文档末尾。

## 1. 本次交付

把 LLM 使用的历史记录改成普通业务数据：知道用户在什么时间关注了什么、当时说了什么、订单实际发生了什么即可。允许同时间同币种出现多条记录和少量重复，不追求严格事件唯一性。

本次必须完成：

1. 订单事件查询使用明确的 SQL 列选择，不查询或返回事件哈希。
2. 历史对话返回原文、角色和发生时间，不返回事件 ID、工具执行轨迹或引用回执。
3. 撤掉 LLM 历史主张的事件引用、回执门禁和自动补查/重写调用。
4. 压缩请求只总结文字，服务端继续记录压缩范围；模型不参与事件编号和来源 ID 生成。
5. 检查现有数据；无存量旧历史时不增加兼容层，完成测试、文档同步和后台服务重启。

**本次不迁移底层 JSONL，不删除数据库表里的 `evt_...` 列或会话日志里的 `ev_...`。** 这些已有内部键继续服务现有消息、工具和投递关联，不进入新的历史读取契约。物理删除存储哈希属于独立迁移，本次 agent 不执行。

本次也不新建记忆表、日志系统、ID 服务、引用别名、唯一性框架、语义裁判或用户标的提取模型。

## 2. 业务标准

| 项目 | 本次规则 |
| --- | --- |
| 历史记录重复 | 允许；读取时不做强制去重 |
| 时间加币种 | 查询和排序条件，不作为唯一键 |
| 不同用户 | 继续使用服务端确认的可见域隔离 |
| 说话内容 | 保留原文，不由模型补写成事实 |
| 未找到记录 | 返回空结果，回答说明当前窗口没有找到相关记录 |
| 检索失败 | 返回明确错误；不能编造历史，也不让附加的引用校验再次阻断整轮 |
| 普通行情回答 | 保持原有自由分析与工具选择 |
| 下单、取消、消息投递 | 保持现有行为；允许日志重复不等于要求重复执行用户操作 |

数据库需要自增主键时，把它留在存储内部即可。已有 `order_id` 是取消订单等业务操作的必要对象标识，可以给模型；不新增 `E0004` 编号体系。

## 4. 模型可见数据契约

### 4.1 对话历史

保留 `search_session_history(keyword, days, limit)` 入口和服务端身份注入。`limit` 仍限制匹配的完整 turn，避免人为切断用户与助手对话；返回内容按消息展开，每条保留自己的时间。

建议结果：

```json
{
  "status": "success",
  "query": "ETH",
  "time_range": {"days": 7},
  "truncated": false,
  "items": [
    {
      "occurred_at": "2026-11-03T17:12:32Z",
      "role": "user",
      "content": "ETH 在2278做空，止损2299，你推荐吗？"
    },
    {
      "occurred_at": "2026-11-03T17:13:51Z",
      "role": "assistant",
      "content": "当时实际保存的助手回答原文"
    }
  ]
}
```

要求：

- 只检索 `user/message`、`assistant/message`、`assistant/local_message` 原文。
- 工具调用计划、工具启动、投递、请求 ID、分支和 checkpoint 不进入这个历史查询结果。订单事实用账本工具查询。
- 标的作为查询关键词即可；历史一句话可能包含多个标的，不新增写入时的币种抽取器。
- 时间来自各条原始事件，不把一个 turn 的用户发送时间当作所有回复的时间。
- 当前提问仍需排除；用于排除的事件键只在函数内部使用，不放进返回值。
- 匹配 turn 超过上限才设 `truncated=true`，不能将结果包装成完整历史。
- 不返回 `event_id`、`user_event_id`、`event_ids`、`receipt_id`、`hit_event_ids`、`retrieval_receipt` 或引用别名。
- 不把匹配 turn 数宣称为用户交易、请求或行为的次数；本次无需提供 `total`。

这里简化的是历史查询工具。当前模型 API 上下文中已发生的工具调用与结果仍需按协议配对，不能为了删历史工具轨迹而破坏实时上下文。

### 4.2 订单事件

查询只选择当前用途需要的列，例如：

```sql
SELECT p.symbol, e.order_id, e.event_time, e.event_type, e.event_price
FROM journal_events AS e
JOIN paper_orders AS p ON p.order_id = e.order_id
WHERE e.session_id = :session_id
ORDER BY e.event_time DESC, e.id DESC
LIMIT :limit;
```

有 symbol/interval 条件时，使用现有规范化逻辑追加参数化过滤，先过滤再 LIMIT。`session_id` 来自服务端上下文。`id` 只用于稳定排序，不必 SELECT 或返回。

模型可见的单条事件：

```json
{
  "symbol": "ETH_USDT",
  "order_id": "ord_example",
  "event_time": "2026-11-04T10:00:00Z",
  "event_type": "order_closed_tp",
  "event_price": 2253.7
}
```

例子的订单号为占位值，实际沿用已有 `order_id`。同秒同币种多条事件全部返回。最新记录先在 SQL 中选出，再按时间正序交给模型读，不能为了升序展示而误取最早的 20 条。

订单总览优先使用表中已有实际成交时间/价格和实际平仓时间/价格；计划价格与成交价格分开。只有原始字段存在时才输出。不要本次再实现净收益计算、手续费模型或仓位重建。

### 5.3 LLM 编排

涉及 `src/core/agent_loop.py`、`src/core/prompt.py`，以及仅被这一机制使用的状态字段。

- 删除 `HistoricalClaimGuard` 调用、自动补查/repair generation、引用检测与降级编排。
- 删除 `src/core/historical_claim_guard.py` 及专属测试。普通的空结果和工具错误在工具结果里表达。
- 删除 `retrieval_receipts`、引用证据登记及仅供引用校验使用的 `evidence_index` 传递链。检查 `agent.py`、`state.py`、`context_builder.py` 和 `context_compactor.py` 的真实调用方后删除，不新增另一种证据索引替代它。
- 保留模型 usage、工具执行、上下文预算、未完成操作与最终回复的正常持久化。
- 最终答复不再需要第二次历史审查模型调用。不要留下永远通过的 guard、开关或兼容分支。

提示词只保留业务要求：历史问题先检索原文；结果截断时说明范围；工具失败时说明取数失败；当时计划、后续事实、新解释分开；不能编造胜率、回填旧条件或把失败包装成成功。

不要求固定回复模板、内部引用或额外 receipt。提示词是表达约束，不是语义正确性的保证。

### 5.4 上下文与旧记录

涉及 `src/infrastructure/memory/context_builder.py`、`context_compactor.py` 和 `src/core/message_protocol.py`。

- 压缩模型只接收上一摘要和原始消息，不附事件 ID，不从模型输出提取事件来源。
- 沿用 `covered_from_event_id`、`covered_to_event_id`、`first_kept_event_id` 等现有内部范围字段；不改父子关系、分支、日志恢复或 checkpoint 关联。
- 不再为 LLM 引用生成新的 `source_event_ids` 集合或 tier。旧 checkpoint 中存在这些字段可以忽略，不迁移已有记录。
- 若需从 `append_compaction()` 移除已无调用者的参数，仅改本模块接口和测试；旧 payload 字段作为历史数据继续存在，不重写日志。
- 历史工具结果只写入并重放 `{occurred_at, role, content}` 当前格式，不转换旧 turn、receipt 或工具轨迹结构。
- 不在读取、压缩或最终回复路径清理旧事件标记。本机默认会话 JSONL 目录为空；若迁入旧归档，迁移前一次性清理，再按当前格式导入。

## 7. 验收

### 自动验收

| 行为 | 验收方式 |
| --- | --- |
| SQL 不选择事件哈希 | 编译 PostgreSQL 方言 SQL，检查 SELECT 列；允许内部 ID 仅出现在 ORDER BY |
| 用户与币种范围正确 | 用两个可见域、两个币种和同秒事件样例验证过滤，LIMIT 后不丢同币种最近记录 |
| 重复记录可读 | 两条相同时间记录都保留，不去重、不报唯一性错误 |
| 历史原文和时间正确 | 用户与助手使用各自时间；当前提问被排除；跨用户不可见 |
| 模型输入干净 | 真实编排的假模型捕获 messages，系统注入的数据不含事件键、引用和 receipt；用户自己输入的 ID 文本不作此断言 |
| 不额外调用模型 | 普通结束只用原有工具循环；不会因历史审查再触发 repair 请求 |
| 空结果/错误明确 | 空查询保持空，查询异常变成工具错误，回复不伪造历史 |
| 当前记录可重放 | 假模型记录历史结果时，读取与重放保持 `{occurred_at, role, content}` 结构一致 |
| 执行链未改变 | 既有工具配对、订单创建/取消、消息投递、会话排队和压缩超限测试继续通过 |

删除引用校验器的专属测试，保留或调整当前业务、作用域、工具协议和压缩测试。不要为每个删除字段新建测试文件，也不使用提示词字符串包含断言作为功能验收。

### 8.2 后台重启

先检查当前是否由现有服务管理器托管；如有，沿用它。当前核对到的启动方式是独立后台进程，下面 Bash 脚本适用于这一方式。

确认当前没有处理中消息再重启：现有进程内队列不跨重启恢复。不要在任务处理中强制杀进程。

```bash
set -euo pipefail
cd /root/pfs_liuyangtong/neodrive_dev/MarketAssAgent
PYTHON_BIN="$(command -v python3)"
"$PYTHON_BIN" --version

mapfile -t BOT_PIDS < <(
  ps -eo pid=,args= | awk '
    $2 ~ /(^|\/)python3(\.[0-9]+)?$/ &&
    $3 ~ /(^|\/)runtime\/cli\/feishu_bot\.py$/ {print $1}
  '
)

if (( ${#BOT_PIDS[@]} > 1 )); then
  echo "发现多个 bot 实例，先核对实际进程再部署"
  exit 1
fi

if (( ${#BOT_PIDS[@]} == 1 )); then
  old_pid="${BOT_PIDS[0]}"
  kill -TERM "$old_pid"
  for _ in {1..20}; do
    if ! kill -0 "$old_pid" 2>/dev/null; then break; fi
    sleep 0.5
  done
  if kill -0 "$old_pid" 2>/dev/null; then
    echo "旧进程尚未退出，停止部署，避免双实例"
    exit 1
  fi
fi

bot_log=/tmp/marketass_feishu_bot_light_history.log
set +m
setsid nohup "$PYTHON_BIN" runtime/cli/feishu_bot.py \
  </dev/null >>"$bot_log" 2>&1 &
new_pid=$!
sleep 3
kill -0 "$new_pid"
ps -p "$new_pid" -o pid=,ppid=,sid=,tty=,stat=,args=
tail -n 30 "$bot_log"
```

命令不写死历史 PID，不替换模型，不修改代理环境。CLI 本身已添加项目导入路径。

核验：只有一个 bot；进程已经脱离启动 shell，stdin 为 `/dev/null`、输出指向日志；出现本次启动后的 WebSocket connected 日志。日志未连接时继续排查，不只凭 PID 存在宣布正常。分享日志时隐去 WebSocket 地址里的凭证参数。
