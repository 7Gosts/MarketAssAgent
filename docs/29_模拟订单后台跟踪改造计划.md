# 模拟订单后台价格跟踪改造

日期：2026-11-17

状态：首版已实施；历史数据修正和主动通知仍待决定

## 目标

复用飞书 bot 进程内已有的 15 分钟轮询任务，按有序价格事件推进活跃模拟订单。监控只看价格先后，不把分析周期当作订单状态判断条件；LLM 不负责周期性查价或决定成交、止盈和止损。

## 当前实现

- `run_plan_tracker` 在原共享循环中先运行计划提醒，再调用 `PaperTradingService.track_active_orders(all_sessions=True)`。没有单独 worker；没有活跃订单时只做数据库扫描，不请求行情。
- 仅跟踪 Gate USDT 加密现货成交。按成交时间和 Gate 成交 ID 排序；K 线 OHLC 不再用来推断同一根 K 线内的入场与退出顺序。`interval` 保留为订单分析上下文，不参与价格事件状态判定。
- `pending_trigger` 订单由价格事件触发入场；订单成交后，只允许后续价格事件触发止盈或止损。待触发订单到期后转为 `expired`。
- 续读游标和少量跟踪状态保存在 `paper_orders.simulation_rule_json.price_tracking`。每轮按页读取；状态、事件和游标在一个数据库事务中提交。失败时回滚当前页并保留原游标，后续轮询重试。
- 新订单先按 `created_at` 建立跟踪起点，已有持仓以 `filled_at` 为起点。初始历史回补每轮最多向前翻 3 页；追平后每轮最多消费一页，积压时后续轮询继续。
- 用户按需查询时，当前会话仍可走同一套价格事件逻辑立即同步；后台任务则显式扫描所有会话。内部成交 ID 仅用于数据游标，不作为 LLM 交易摘要字段。
- 现有逻辑只更新模拟账本和轮询日志；订单状态变化尚未自动回送 LLM 或推送飞书。模拟价格源是 Gate 现货成交，不代表用户真实账户成交或合约标记价格。

## 数据缺口与失败行为

- Gate 请求失败、事件格式无效或无法建立历史起点时，不推进游标、不猜测期间是否成交；本轮记录失败并在下次轮询重试。
- 单轮未追平时只提交已处理页的游标，逐轮继续消费，不跳到最新成交 ID。
- 首版只支持 Gate USDT 加密现货订单；其他市场保持账本状态，不伪装成已被后台价格跟踪。
- 该实现不会追溯修正旧订单。T00007 的历史止盈与入场时间问题尚未改写生产账本，需单独确认数据更正方案。
