# 轻量历史记录与事件序号迁移

日期：2026-11-04

状态：代码、JSONL 与 PostgreSQL 数据迁移及后台部署完成；真实对话验收待后续用户消息。

## 1. 决策

事件哈希不是业务事实，也不作为记录主键：

- PostgreSQL `journal_events` 使用已有自增 `id`；删除字符串 `event_id` 列与唯一索引。现有行保留，时间、类型、价格和订单关系不变。
- JSONL 信封使用格式 v2。事件位置是 session 内单调 `seq`，关系字段使用 `parent_seq` 与 `*_seq`。跨 session 的定位使用 `(session_id, seq)`。
- 允许同一时间、币种、价格或类型的重复业务行；这些字段只用于查询和排序，不作为唯一键。
- `session_id`、`branch_id`、业务 `order_id`、副作用 `operation_id` 保留。`idempotency_key` 用于入口/操作重试，`record_checksum` 和 blob hash 用于完整性校验；它们不是事件主键。

LLM 历史工具只返回逐消息 `{occurred_at, role, content}`。订单工具只读取当前用途所需列，并在 SQL 中按服务端 session、标的与周期过滤。模型输入不包含日志序号或数据库主键。

## 2. JSONL 格式

新 envelope 的身份与顺序字段：

```json
{
  "format_version": 2,
  "session_id": "sess_...",
  "seq": 42,
  "branch_id": "br_...",
  "parent_seq": 41,
  "event_type": "assistant/message"
}
```

移除 `event_id`、`parent_event_id` 和所有 `*_event_id` 关联字段。父子链、模型请求、工具、投递、checkpoint 和分支引用均改用同 session 的整数 `seq`。普通重复事实可追加为不同序号；入站外部消息与副作用操作仍按业务幂等键保护。

## 3. 存量数据迁移

迁移前默认数据根为 `/root/.marketassagent/context`，无自定义 `MARKETASSAGENT_DATA_DIR`。旧数据盘点为 3 个 session、2,638 条 v1 事件、34 个历史搜索结果和 317 个 blob 引用。旧历史检索 blob 合计约 1.42 GB，包含嵌套工具轨迹与 receipt。

`ops/migrations/migrate_jsonl_event_sequences.py` 在服务停止后一次性执行：

- 按 session 建立旧 `event_id -> seq` 映射，转换父链和 payload 内的已知关联字段；删除 checkpoint `source_event_ids`。
- 把旧历史检索 turn 转为用户/助手消息，丢弃嵌套工具结果、receipt 与匹配总数。助手没有独立时间戳时不借用用户时间；用户原文保留。
- 更新历史模型请求中的旧工具结果、内部引用标记和请求内容 hash。历史请求因此不再保证按旧字节原样复现；迁移后的请求 hash 与 blob 引用自洽。新请求仍按当前代码完整记录。
- 重算 envelope checksum、重建 head/index，并删除不再被日志引用的 blob。
- 迁移前复制完整 context 根目录，备份目录由命令显式指定。

本次结果：3 个 session 全部可恢复；310 个模型请求 blob 校验通过；34 个旧历史结果已扁平化；活跃 blob 从约 1.48 GB 降至约 48 MB。

## 4. PostgreSQL 迁移

本机数据库迁移前为 16 条 `journal_events`、6 条 `paper_orders`、6 条 `journal_ideas`；旧 `event_id` 唯一索引没有业务引用。`alembic_version` 不存在，沿用项目手工 SQL migration，不运行 Alembic。

执行 `ops/migrations/20261104_drop_journal_event_hash.sql`：删除 `uq_journal_events_event_id` 和 `journal_events.event_id`，保留主键 `id` 与全部业务行。迁移前的 `id,event_id` 对照暂存于 `/tmp/marketassagent_journal_event_id_backup_20261104.csv`，权限为 `0600`。

迁移后复核：事件 16 行、订单 6 行、idea 6 行；仓储查询返回 `symbol, order_id, event_time, event_type, event_price`，不再有 `event_id` 属性。

## 5. 代码归属

- `event_schema.py`、`event_store.py`：v2 信封、整数序号、父链与投影。
- `session_journal.py`、`context_builder.py`、`context_compactor.py`：所有事件关联改用 `seq`。
- `conversation_service.py`、`agent_loop.py`、`tool_protocol.py`：序号在同一 session 内传递；历史检索排除当前消息时使用 `(session_id, seq)`。
- `models.py`、`paper_trading_repository.py`、`sim_account.py`：订单事件使用数据库自增 `id`，重复行允许保存。
- `message_protocol.py`、`session_history.py`：没有事件 ID 清洗器或旧格式转换器；当前格式由数据源直接生成。
