# 可信行情分析优化方案

日期：2026-10-15

状态：复盘提示词已实施；已用真实原文和模拟台账收敛核对范围，尚未接入机械评分或历史价格核对工具。

依据：[21_行情事实与决策分层方案.md](21_行情事实与决策分层方案.md)、[24_可信行情分析报告.md](24_可信行情分析报告.md)

## 1. 目标与边界

行情分析是可证伪的概率假设。长期目标是足够连续样本、固定规则、计入成本后的正期望，不是每次预测正确；高胜率本身也不保证盈利。允许失败、止损和证据不足，不用后续走势替旧建议补条件。

- 普通行情问答继续由 LLM 自主选工具、解释结构和提出条件计划，不强制固定模板。
- 历史复盘分开呈现当时原文、后续事实和新解释。明确失败直接暴露，不能用“方向最终正确”改判订单盈利。
- 先复用历史检索和模拟台账。后续只补真实案例需要的有界价格事实核对，不做通用自然语言计划解析器、回测框架或多模型裁判。
- 不新增数据库表、订单状态、长期记忆或依赖，不改变现有 Agent Loop。

## 2. 当前能力与调用链

```text
ConversationService -> 事件日志与上下文压缩 -> NativeAgentLoop -> ToolExecutor
  -> search_session_history：当前可见域内定位原文与 event_id
  -> get_journal_status：当前会话模拟订单与事件
  -> LLM：区分证据和解释，保留失败与不确定性
```

| 能力 | 已有边界 |
| --- | --- |
| `search_session_history` | 检索历史原文，不把摘要当原始计划；多版本不能拼成一个获胜计划 |
| `scan_scope / resolve_event_payload` | 读取活动分支、完整 blob；外域或原文缺失不能取证 |
| `HistoricalClaimGuard` | 校验历史引用与检索完整性，不证明价格角色、因果或收益正确 |
| `get_journal_status` | 只读当前会话的模拟台账；最多取最近 50 条订单、20 条事件，关闭列表只返回最近 10 条，不是完整统计样本 |
| `fetch_market_data` | 当前公开接口只取最新行情，不能验证任意历史窗口 |
| Gate 历史 K 线 | `from/to` 已实测可用，但尚未接入项目历史核对工具 |

`reconcile_paper_orders` 会更新订单状态，不是只读取证；不能为了写复盘隐式调用它。模拟台账记录的是本项目模拟结果，不是用户实盘成交证明；字段和事件不足时，不补造费用、滑点、精确收益或执行路径。

## 4. 核对范围

把价格事实、触发条件和交易结果分开，不用一个“有效/无效”覆盖所有问题：

| 问题 | 判定口径 | 实施状态 |
| --- | --- | --- |
| 当时到底建议了什么 | 完整原文、事件时间、版本和分支；未写的条件不得回填 | 原文读取已有；条件的语义核对仍由人或 LLM 完成，不是代码证明 |
| 后续是否到过一个明确价位或区间 | 在指定的后续已收线 K 线内，检查 `low <= upper and high >= lower`；只是该根价格范围与区间相交 | 可机械计算，但历史取数和核对工具尚未接入 |
| 后续是否收上/收下明确阈值 | 按原文周期比较已收线 `close` 与阈值；明确报告实际收线时点 | 可机械计算，但只验证单个价格条件，不自动验证整个计划 |
| 受阻、止跌、站稳、放量等确认是否完成 | 原文未定义阈值、持续根数或顺序时，返回未量化、不可机械验证 | 不建立关键词评分，不事后选择一个有利定义 |
| 模拟订单是否成交、取消或止损 | 指定订单的台账状态与事件；区分取消和止损 | 复用 `get_journal_status`，失败或超出可见记录时明确缺证据 |
| 原方案能赚多少、支撑是否有效、方法是否有优势 | 需要完整触发/退出/分批/成本规则及连续样本 | 当前不评分，不从价格触及或两笔交易推导命中率、正期望 |

即使计算成功，也不能把“到过阻力带”说成“阻力预测正确”，不能把“收上阈值”说成“放量突破条件全部完成”。同一根 OHLC 内的先后次序、瞬间穿越和实际成交不能由最高最低价还原。

## 5. 后续价格核对的最小边界

如下一步实现工具，第一版只做区间相交或收线越过阈值的事实查询，不模拟完整交易，不输出胜负或 R。接口留到选定一个真实核对案例后确定，不提前建立计划 schema 或全文条件解析器。

- 使用服务端 `ToolContext` 读取当前可见域内的精确事件及完整原文；不接受身份、路径或跨域参数。原文不存在、缺 blob、标的/周期/价位角色不明确时不猜。
- 核对对象必须指向原文中的具体价位、周期和分支；不能把另一个版本的数字或条件拼进来。若需要代码猜测自然语言条件归属，就缩减为事实展示，不宣称已验证计划。
- 历史数据复用 Gate HTTP 封装和现有转换，来源明确区分现货与合约。现货触价不能冒充合约成交、清算或实盘收益。
- 固定观察事件之后 24 根已收线 K 线，标明这是查询窗口，不是原建议有效期。整根处于发言之后的记录才可判断后续触及；发言所在根若跨越目标价位，无法判定发生在发言前还是之后，应单独标记时间歧义，不算入后续触及。
- 不足 24 根、缺根、未收线或坏数据时保留窗口不完整；可以展示已取得的事实，但不能把已观察到的“未触及”当成整个窗口未触及。不回退最新行情，不拼其他源掩盖缺失。
- 返回原文、事件时间、查询区间、数据源、已观察事实及不可验证项。LLM 可以提出新解释，但不得将计算结果升级为条件完成、盈利或方法有效。

不新增叙事摘要、评分表或第二套存储，调用轨迹仍由现有 EventStore 记录。一次调用扫描一次可见域为 O(E)，窗口计算为 O(B)，B 固定为 24；当前不做批量检索，主要新增耗时在 Gate 网络 I/O，不先建索引或框架。

## 6. 已实施规则与验收

生产表达约束集中在 `src/core/prompt.py`：

1. 技术分析按概率假设表达，不编造无统计依据的胜率。
2. 复盘取原文，不回填旧条件；止损不能改判盈利，单次止损也不自动证明计划设计错误。
3. 缺证据时保留不可验证和归因不足，不根据画像或进出场终值断言违纪或全程守纪律。
4. 未隔离未来行情与上下文时不能声称严格盲测，少量成功样本不能证明正期望。
5. `level_zones_v1.touches` 是候选聚集数量，`strength` 不是历史命中率，两者不能证明独立触碰或验证次数。

真实对话验收关注业务含义，不锁定提示词措辞：

- 问“2490 是不是提前进场”：查原方案版本，不能只引用后来 2508–2515 的方案；缺完整执行路径时不判断受阻条件是否满足。
- 问“2539 多是否未等 2587 确认”：区分回踩与突破分支，不回填条件；台账止损仍保留失败。
- 问“阻力是否有效”：触及、反应和方法优势分别讨论，没统计不报命中率。
- 问“只看过去做盲测”：当前无法隔离未来，坦白是事后复盘，不能声称完成严格盲测。
